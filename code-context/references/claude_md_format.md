# CLAUDE.md 格式说明

每个业务模块目录下都应该有一个 `CLAUDE.md` 文件，用于描述该模块在系统中的角色和功能。

**注意**：对于 Xcode/iOS 项目（包括 SwiftUI、UIKit 等），文件名会使用路径格式：`CLAUDE_<folder1>_<folder2>.md`，以避免在同一目录下有多个 CLAUDE.md 文件。

## 文件结构

```markdown
# {模块名称} 模块

## 地位 (Position)

本模块在系统中负责：{简短描述模块的职责和在系统中的位置}

## 逻辑 (Logic)

本模块在系统中执行：{描述模块的主要功能和业务逻辑}

## 约束 (Constraints)

使用本模块时需遵守以下约束：

{列出使用该模块时需要遵守的规则和限制}

## 业务域清单

本模块包含以下子模块和功能：

| 名称 | 类型 | 功能描述 |
|------|------|----------|
| {子模块/文件名} | {module/directory} | {功能描述} |
| ... | ... | ... |

## 依赖关系

本模块依赖以下外部模块：
{列出依赖的模块}

本模块导出以下内容：
{列出导出的接口、类、函数等}
```

## 字段说明

### 地位 (Position)
- **目的**：说明模块在系统架构中的位置和角色
- **内容**：应该回答"这个模块负责什么？"
- **示例**：
  - "API 层 - 处理 HTTP 请求和响应"
  - "业务逻辑层 - 实现核心业务功能"
  - "数据访问层 - 管理数据库操作"

### 逻辑 (Logic)
- **目的**：描述模块实现的主要功能
- **内容**：应该回答"这个模块做什么？"
- **示例**：
  - "定义 RESTful API 端点，路由请求到相应的服务层"
  - "实现用户认证和授权逻辑"
  - "处理数据验证和转换"

### 约束 (Constraints)
- **目的**：列出使用该模块时必须遵守的规则
- **内容**：应该回答"使用这个模块有什么限制？"
- **示例**：
  - "所有端点需要进行适当的身份验证和授权"
  - "请求参数必须通过 Pydantic 模型验证"
  - "服务应该是无状态的"

### 业务域清单
- **目的**：列出模块包含的所有子模块和文件
- **内容**：表格形式，包含名称、类型（module/directory）、功能描述
- **示例**：
  | 名称 | 类型 | 功能描述 |
  |------|------|----------|
  | user.py | module | 用户管理功能 |
  | auth.py | module | 认证相关功能 |
  | services | directory | 业务服务子模块 |

### 依赖关系
- **目的**：说明模块的输入输出
- **内容**：
  - 依赖的外部模块列表
  - 导出的接口、类、函数列表

## 自动生成

`CLAUDE.md` 文件可以由 `analyze_module.py` 脚本自动生成或更新。脚本会：

1. 扫描目录下的所有代码文件（支持多种编程语言）
2. 分析每个文件的导入、类、函数
3. 推断模块的功能和依赖关系
4. 生成或更新 `CLAUDE.md` 文件

**Xcode/iOS 项目特殊处理**：
- 自动检测 Xcode 项目（查找 `.xcodeproj`、`Package.swift` 或 `Podfile`）
- 使用路径命名：例如 `Features/Auth/` 目录会生成 `CLAUDE_Features_Auth.md`
- 避免多个模块在同一目录产生文件名冲突
- 适用于所有 iOS/macOS 项目（SwiftUI、UIKit、Swift 等）

## 手动维护

自动生成的内容可能不完整，建议在生成后手动补充：

1. **更准确的功能描述**：自动推断可能不够准确
2. **具体的约束条件**：自动生成只有通用约束
3. **业务逻辑说明**：补充关键的业务规则
4. **设计决策**：记录重要的架构决策
