# 试试这个Prompt，它为技术小白把关Vibe Coding过程

前两天我听了Lenny's Podcast，嘉宾是Zevi Arnovitz，Meta的一位非技术背景的PM。  
他分享了一个特别聪明的做法，就是用ChatGPT Project创建了一个"虚拟CTO"。

所谓“虚拟CTO”，实际上是一个Prompt，帮助没有技术背景的人，在build任何东西之前，先明确要做的是什么。  
然后将任务拆分成若干阶段，为每个阶段创建使用的Prompt，提供给Cursor等编程工具，并根据Cursor的返回，检查潜在的问题。  

## 为什么需要一个虚拟CTO?

作为一个非技术背景的人，你肯定遇到过这种情况。

你有个想法，想做个功能，或者产品。  
但是你不知道从哪开始，不知道技术上怎么实现，不知道有没有坑。

然后你就问ChatGPT。

ChatGPT会怎么回答呢?  
它会说："好的！这是个很棒的想法！我们可以这样做..."  
然后给你一堆看起来很专业的建议。  

但是问题来了。

**AI太舔狗了。**

Zevi在播客里讲了一个特别搞笑的故事。  
有一次他问ChatGPT，Bun JavaScript是不是跟Zustand类似。  
这俩玩意完全不是一个东西。  
但是ChatGPT说："是的！它们完全一样！"  
然后开始胡说八道。  
Zevi说不对啊，这俩根本不一样。  
然后ChatGPT说了一句让他崩溃的话：

"哦抱歉，我以为你是在编故事，我在配合你即兴发挥。"

我看到这里的时候，真的笑死。

但是，这就是普通AI的问题，它太想讨好人类了，以至于会同意我们所有愚蠢的想法。  
如果把它当作你的CTO，推进项目开发，那基本上你的项目就废了。

所以，Zevi做了一件特别聪明的事。  

他创建了一个ChatGPT Project，给它设定了一个严格的Prompt，让它真正像一个CTO一样工作。  
不是舔狗，而是会挑战你、会推回你、会问你问题的CTO。

## 这个CTO Project到底是什么?

简单来说，就是一个定制化的ChatGPT对话空间。

你给它一个超级详细的system prompt，定义清楚它的角色、职责、工作方式。  
然后每次你跟它对话，它都会按照这个设定来工作。  
Zevi的这个Prompt模板，我觉得设计的特别好。  
它包含了几个核心部分：

**1. 角色定位**

明确告诉AI：你是CTO，我是产品负责人。  
我负责产品方向和用户体验，你负责技术实现。  
你的目标是快速交付、保持代码质量、控制成本、避免回归问题。

**2. 技术栈信息**

把你的项目用的所有技术都列清楚。  
前端用什么，后端用什么，数据库用什么，支付用什么。  
这样AI就能给你更精准的建议。  

**3. 工作方式**

这个是最关键的部分。  

告诉AI：  
- 以 CTO 的身份行事。**在必要时你必须提出反对意见**，不需要一味迎合；你的责任是确保我们成功。
- 先确认理解，再给方案
- 默认先给高层计划，再给具体步骤
- 不确定的时候要问问题，不要瞎猜
- 用简洁的要点列表回答
- 在合适的情况下，**建议自动化测试和回滚方案**

**4. 工作流程**

这个才是精华。
它定义了一个完整的7步工作流：

1. 我们brainstorm一个功能或者我说一个bug
2. 你问我所有澄清性的问题，直到你确定理解了
3. 你创建一个discovery prompt给Cursor，收集所有需要的信息
4. 我把Cursor的回答返回给你，你再问我需要的补充信息
5. 你把任务拆成几个阶段
6. 你为每个阶段创建Cursor prompts，让Cursor返回状态报告
7. 我把这些prompts传给Cursor，然后把状态报告返回给你

看，这是一个完整的产品开发协作流程。

## 这个方法有用吗

有用。  
我试了之后，发现有几个特别大的好处。

**第一，它会challenge你**

不像普通的ChatGPT，这个虚拟CTO会真的会提出反对意见。  
比如你说想加个功能，它会问你：

- 这个功能解决什么问题？
- 有多少用户需要这个？
- 有没有更简单的方案？
- 这个会不会影响现有的功能？

就像一个真正负责任的CTO会问的问题。

**第二，它会把复杂问题拆解**  
最厉害的是那个7步工作流。  
它不会直接给你一个大方案，让你不知道从哪开始。  
而是会先帮你理解问题，然后拆成小任务，每个任务都有明确的输入输出。  
这样你就算不懂技术，也能一步一步推进。

**第三，它会帮你review**  
每个阶段做完，它都会让Cursor返回状态报告。  
然后它会review这些报告，看有没有问题，有没有风险。  
这个对于不懂代码的人来说，太重要了。  
因为**你自己看不出来代码有没有问题**，但是AI可以帮你审查。

**第四，它会记住上下文**  
因为是在一个Project里，所有的对话都在同一个上下文。  
它会记住你的技术栈，记住你之前做过的决策，记住你的项目结构。  
不用每次都重新解释一遍。  

## 怎么开始使用?
如果你想试试这个方法，可以这样开始。 

**第一步：创建ChatGPT Project**  
在ChatGPT里，点击左上角，选择"Create Project"。

然后把上面那个Prompt模板复制进去。  
记得把里面的技术栈改成你自己的。

**第二步：准备好你的技术栈信息**  
哪怕你不懂技术，也要知道你用的是什么。  
比如：
- 前端：React还是Vue？
- 后端：用不用Supabase？
- 数据库：Postgres还是MySQL？
- 部署：Vercel还是自己的服务器？

如果你完全不知道，那就用最简单的组合：
- 前端：React + Vite + Tailwind
- 后端：Supabase
- 部署：Vercel

这个组合基本上可以做90%的产品了。

**第三步：开始第一个对话**  
不要一上来就说"帮我做个Facebook"。  
从一个小功能开始。  

比如：  
"我想做一个简单的待办事项应用，用户可以添加、删除、标记完成。数据要保存在云端。"

然后让虚拟CTO问你问题，你一个一个回答。  

**第四步：配合Cursor使用**  
这个工作流的精髓，是ChatGPT和Cursor的配合。

ChatGPT负责理解需求、拆解任务、review代码。  
Cursor负责实际写代码、执行。  
所以你需要在两个工具之间来回切换，把信息传递过去。  
刚开始可能会觉得有点麻烦，但是用几次就习惯了。
